# GDB 使用指南设计

## 目标

在仓库根目录新增中文 `gdb.md`，说明如何使用现有命令行脚本和 VS Code 配置调试 `build/bin` 下的程序。

## 读者与范围

文档面向刚开始使用 GDB 的项目开发者，以可以直接复制执行的命令为主。内容覆盖：

- 准备 Debug 构建；
- 选择和启动 `build/bin` 下的程序；
- 向被调试程序传递参数；
- 使用 VS Code 启动调试；
- 日常断点调试所需的常用 GDB 命令；
- 与当前项目配置直接相关的故障排查。

不展开 GDB 内部原理、远程调试、内核调试或完整汇编教程。

## 文档结构

1. 环境要求与 Debug 构建。
2. 命令行快速上手，包括查看程序、启动无参数程序和传递参数。
3. 一次完整的断点调试示例。
4. VS Code F5 调试流程和 `args` 数组配置。
5. 常用命令速查表。
6. 当前配置文件及其职责。
7. 程序不存在、缺少调试符号、断点无效及 VS Code 启动失败的排查方法。

## 示例原则

- 使用仓库中确实存在且无需模型即可进入 `main` 的 `simple-ctx` 作为基础示例。
- 使用 `gpt-2-sched` 展示带程序参数的调用形式，但不假设模型文件一定存在。
- 所有命令默认从仓库根目录 `/home/jhtang3/ggml/ggml` 执行。
- 明确区分 GDB 自身参数与被调试程序参数。

## 验证

- 检查 Markdown 格式和空白错误。
- 对照 `scripts/gdb-bin`、`.vscode/launch.json`、`.vscode/tasks.json` 和 `gdb/ggml.gdb` 核对名称及路径。
- 执行文档中的 Debug 配置、脚本帮助和 `simple-ctx` 批处理断点示例。
- 保证用户已有的 `get_gpt2.sh` 未提交修改不受影响。
